我让 AI Agent 在雪球自动发股评——多阶段质量门禁管线实战

发表于2026-09-02|更新于2026-09-02|技术实践

从数据采集到发布上链，4 个阶段 6 道闸门——这是我构建雪球自动发股评管线踩过的所有坑。

1. 缘起 — 为什么搞这个

我有一套覆盖 A 股 5000+ 只股票的数据采集系统（stock-mcp-server，128 个工具、15 个数据源），每天能自动抓取实时行情、技术指标、资金流向、龙虎榜、公告、研报……数据很全，但数据不等于内容。

雪球上有大量作者每天发收盘复盘、盘前早报、个股分析。如果我能用 AI 把这些数据自动写成文章发到雪球，相当于给我的数据系统装了一个”变现出口”。

听起来简单——调 LLM 写篇文章然后发出去不就行了？

实际操作下来，我踩了至少 15 个坑，写了 6000+ 行 Python，最终搭出了一条 4 阶段、6 道闸门的管线。这篇文章就是这些坑的完整记录。

2. 核心方法 — 四阶段六闸门

2.1 管线全貌

关键设计原则：确定性方案做主力，LLM 做加分项。

数据采集完全程序化（API 调用 → JSON 快照），数字渲染由模板引擎完成（LLM 不碰数字），评审环节程序化闸门在前、LLM 主观评审在后。LLM 只负责两件事：把数据写成可读的文章，以及从读者视角给出主观评价。

2.2 数据采集：快照为王

每个文章类型有一个 collect_xxx.py，负责拉取所有需要的数据并保存为快照 JSON：

快照的意义：所有数字从此不再经过 LLM。LLM 只看到”贵州茅台现价 1523 元”的事实块，而不是让它自己查数字。

2.3 文章生成：事实块 + 模板约束

事实块的构建代码有 300+ 行，负责把快照 JSON 翻译成 LLM 能理解的结构化数据：

LLM 拿到的就是这些事实块 + 模板，它的工作是”把数据写成人话”，而不是”编造数据”。

2.4 质量评审：6 道闸门

这是整条管线的核心。每道闸门都是独立的程序化校验，任何一个不过就阻止发布：

闸门 类型 检查内容 退出码
① 正文有效性 硬门禁 占位符检测 + 最短长度 + 必须含市场数字 exit 4
② 数据暂缺 硬门禁 “数据暂缺”/“暂无数据” 等占位表述 exit 4
③ 英文板块名 硬门禁 TV REST fallback 返回英文 GICS 名称 exit 4
④ 数字一致性 硬门禁 文章数字 vs 快照数字逐项比对 exit 2
⑤ 敏感词合规 硬门禁 收益承诺/操作建议/目标价检测 exit 5
⑥ LLM 读者评审 软评审 标题吸引力 + 合规红线 + AI味检测 参考

前 5 道是程序化的硬门禁——不依赖 LLM，每次都能稳定执行。第 6 道是 LLM 主观评审，仅作参考。

闸门 ⑤ 敏感词合规（最复杂的一道）

设计的关键点：“不建议买入”不能被误杀。所以操作建议类需要先检测否定语境，再决定是否拦截。

2.6 LLM 选择：确定性兜底 + LLM 加分

这里有一个重要的工程决策：不用最聪明的 LLM，用最稳定的 LLM。

模型 中文短输出 稳定性 成本
mimo-v2.5 ❌ 3/3 空返回 不可用 -
agnes-2.0-flash ✅ 5/5 成功 可靠 低
deepseek-v4-flash ✅ 稳定 可靠 低

mimo-v2.5 在短输出场景下直接返回空字符串（3 次调用 3 次空返回），最终切换到 agnes-2.0-flash。LLM 短输出不稳定时，不要加重试次数——直接换模型。

3. 踩坑记录 — 15 个真实 bug

3.1 LLM 输出的 preamble 污染

LLM 写完文章后经常输出一段”好的，以下是根据您提供的数据撰写的分析……”，这段寒暄被当成正文一起发布。

修复：strip_llm_preamble() 逐行扫描，跳过 18 种 preamble 模式：

更隐蔽的问题：LLM 修订时会把提示词中的 meta 标记（# 标题、# 输出、# 原文）原样复制进正文。这些也需要清除。

3.2 “数据暂缺”占位

LLM 在数据不全时会写”数据暂缺”或”暂无数据”——这比不写更糟，因为读者看到的是”这个作者没数据还在发文章”。

修复：生成侧 prompt 改为”无数据整节省略”，评审侧硬门禁拦截任何占位表述。双保险。

3.3 英文板块名泄漏

TV REST 全市场列表作为主数据源时，东财 push2 限流 502 会 fallback 到 TV REST，返回的行业名是英文 GICS 分类（”Integrated Oil”、”Major Banks”）。

修复：评审闸门检测 Title Case 英文短语，命中即拒绝发布。

3.4 LLM 评审 JSON 解析崩溃

LLM 评审返回的 JSON 字符串值内可能含未转义英文引号 → json.loads 抛异常 → 评分丢失。

修复：_parse_review_json() 实现了三级降级：

  1. 标准 json.loads
  2. 代码块提取 ```json {...} ```
  3. 字段级正则兜底（独立提取 score/suggestions/pass）

3.5 numpy.bool_ 序列化爆炸

辩论模块 _format_dossier 用 json.dumps 序列化数据时，numpy.bool_ 类型不被 JSON 支持 → TypeError: Object of type bool_ is not JSON serializable。

修复：3 处 json.dumps 加 default=str。

3.6 LLM 空返回

最离谱的 bug：mimo-v2.5 在短输出场景下返回空字符串，但状态码是 200。代码拿着空字符串继续执行 → 生成的”文章”只有事实块和模板，没有正文。

修复：空返回立即检测 + 空串最小长度检查 + 模型切换到 agnes。

3.7 修订器评分 N/A

LLM 评审时输出 "score": "N/A"（字符串而非数字）→ 后续代码 float("N/A") 报错。

修复：_extract_score 显式处理 “评分 N/A” → 返回 None；LLM 提示词要求 “score 必须是数字”。

3.8 占位符文章逃逸

LLM 429 时 generate_article 生成占位符”文章生成服务暂时不可用”，数字校验无数字可比对 → 判通过 → 占位符文章被发布。

修复：正文有效性闸门检测 3 个占位符关键词。

3.9 权益提升带来的合规压力

雪球创作者权益开通后流量上升 → 内容合规风险同步上升。之前”生成时约束”就够了，现在需要”发布前硬门禁”。

修复：新增 5 种收益承诺模式 + 6 种操作建议模式 + 否定语境豁免。

3.10 LLM 旁白混入正文

LLM 会在文章中写”（注：由于事实块中未包含XX数据，本小节按要求省略。）”——这不是写给读者的，是 LLM 的自我解释。

修复：正则清除 （注：...省略/略过/不写...） 类旁白。

4. 总结 — 核心 takeaway

确定性方案做主力，LLM 做加分项。这条原则贯穿了整条管线：

  • 数据采集：纯程序化（API → JSON），不经 LLM
  • 数字渲染：模板引擎完成，LLM 不碰数字
  • 评审闸门：5 道程序化硬门禁 + 1 道 LLM 软评审
  • 合规检测：模式匹配 + 否定语境豁免，不依赖 LLM 判断

LLM 只做两件事：把数据写成人话 + 从读者视角给主观评价。一旦 LLM 出问题（空返回、JSON 崩溃、preamble 污染），管线的程序化闸门能把控质量底线。

一句话总结：不要让 LLM 做它不擅长的事（保持数字准确、保持格式稳定、保持合规边界），让它做它擅长的事（自然语言表达、读者视角评价）。

项目规模：6000+ 行 Python，4 种文章类型（收盘复盘 / 盘前早报 / 周度复盘 / 个股分析），60+ 个文件。
