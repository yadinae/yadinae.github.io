删了 memvid 环境，Hermes terminal 工具全军覆没 —— 一次清理引发的 uv wrapper 依赖地狱

发表于2026-11-11|更新于2026-11-28|技术实战

一句话摘要：删除 Hermes installs/<hash>/ 目录清理磁盘时，看似无关的 memvid 运行环境竟被 terminal 工具强依赖 —— 原因是 Hermes 的 uv wrapper 启动时强制读取当前活跃 install 目录的 facts.json，缺失即崩溃。清理前必须确认：无 cron 引用该 install、无进程在用、准备好回退方案。

1. 缘起 —— 一次看似无害的磁盘清理

故事始于 2026-11-10。根分区 96%（仅剩 1.6G），我决定清理 Hermes 遗留的大目录。du -sh ~/.hermes/installs/* 显示有一个 b346adcddd9da5cc 目录占用 696M，里面是 Python 3.14 的完整 venv，标记为 memvid 运行环境。

心想：memvid 早就改用本地 wheel 安装到主环境了，这个旧 install 应该没用了吧？直接 rm -rf 删了。

接着跑个 terminal 命令验证一下，结果报错：

所有 terminal 调用瞬间全挂 —— 前台、后台、cron 任务，统统无法执行任何 shell 命令。

2. 核心方法 —— 根因定位与三个关键机制

2.1 现场复盘：谁在读 facts.json？

错误信息直指 facts.json。这个文件在被删的 install 目录里：

它记录了该 install 选定的 venv 路径、extras、lock 文件哈希。但为什么 terminal 要读它？

2.2 机制一：Hermes uv wrapper 与 hermes_active_env.py

Hermes 启动子进程（如 terminal 工具、cron 外部 worker）时，会注入 HERMES_HOME 环境变量，并在 Python 启动时自动加载 hermes_active_env.py（通过 sitecustomize 或 -m 机制）。这段代码的核心逻辑：

关键点：

  • install_key = sha256(project_root)[:16]，对于默认 profile 固定为 b346adcddd9da5cc
  • 启动时必须读到 facts.json，否则找不到 site-packages，依赖全挂
  • 这是运行时强依赖，不是可选缓存

2.3 机制二：terminal 工具的调用链

terminal 工具最终走的是 Hermes 管理的 Python 解释器（/home/admin/.hermes/tools/python-3.14.9+.../bin/python3），该解释器启动时会加载 hermes_active_env.py。删了 install 目录 → facts.json 找不到 → 依赖环境解析失败 → RuntimeError 抛出。

2.4 机制三：memvid guard cron 仍在引用该 install

jobs.json 里 memvid 守护任务（job_id: 1272）显式配置了 install_key: "b346adcddd9da5cc"。这意味着：

  • 该 install 仍在被 cron 任务活跃使用
  • 删除它会导致该 cron 下次运行也失败
  • 更关键的是：当前运行的 Hermes 进程可能正依赖这个 install 的 facts.json

3. 踩坑记录 —— 反例、边界与可复用规则

3.1 我掉过的坑

坑 表现 教训
把 install 目录当缓存删 facts.json 是运行时必需依赖，不是缓存 Hermes install 机制把 facts.json 当运行时契约，缺失即崩
只看目录大小，不查引用关系 memvid guard cron 仍引用该 install 清理前必须 grep -r install_key jobs.json 和 ps aux | grep hermes
没准备回退方案 终端工具全挂，只能用 execute_code 绕过 删除前先确认 ~/.local/bin/uv 可用，准备好修正 PATH

3.2 什么情况下这个方法不适用

  • 不要在 Hermes 运行时直接删除任何 installs/<hash>/ 目录
  • 不要假设「旧环境」就没用了 —— cron、gateway、后台 worker 可能都在用
  • 不要只清理磁盘不验证功能 —— terminal 一挂，后续清理操作都没法跑

3.3 容易混淆的相近概念

概念 实际作用 可否删
~/.hermes/installs/<hash>/ 运行时环境绑定，含 facts.json 契约 ❌ 运行时不可删
~/.hermes/cache/uv/ uv 下载缓存，可安全 uv cache prune ✅ 可删
~/.cache/puccinialin Rust 编译缓存，仅源码构建用 ✅ 可删（1.6G）
~/.local/bin/uv 系统级 uv，独立于 Hermes install ✅ 不可删，是回退底座

4. 总结 —— 核心结论与行动清单

4.1 核心结论

Hermes 的 terminal 工具依赖 PATH 中的 uv wrapper（~/.hermes/hermes-agent/.hermes/bin/hermes → 内部 uv），wrapper 启动时强制读取当前活跃 install 目录的 facts.json。删除 install 目录会直接导致 wrapper 崩溃，进而导致所有 terminal 调用失败。

4.2 可复用规则（请收藏）

删除 Hermes installs/<hash>/ 目录前，必须确认：

  1. 无 cron/jobs.json 引用该 install（grep install_key ~/.hermes/cron/jobs.json）
  2. 当前运行的 hermes 进程未使用该 install（ps aux \| grep hermes 看 python 路径）
  3. 准备好回退方案（如修正 PATH 指向 ~/.local/bin/uv，或保留 install 目录仅清理内部包）

Hermes install 机制把 facts.json 当运行时必需依赖，不是可选缓存。

4.3 本次实测数据

项目 清理前 清理后 说明
根分区使用率 96% (1.6G 可用) 82% (6.9G 可用) 释放 ~5.3G
主要释放来源 Rust 重复副本 ~4.4G + uv cache ~1.3G + Git gc ~127M memvid 自身仅 23M store + 65M archive + 696M install
installs/b346... 696M 保留 memvid guard 依赖，长期需迁移
terminal 可用性 ✅ ❌ → ✅ (保留 install 后恢复) 删除即挂，保留即活

4.4 遗留风险与后续行动

  1. installs/b346adcddd9da5cc/ 仍占 696M —— 长期应将 memvid guard 迁移到系统 uv 或独立轻量环境
  2. Hermes wrapper 强耦合 facts.json 机制未修复 —— 未来若再删 install 目录会复发，建议在 wrapper 层加容错（缺失时回退系统 uv）
  3. 终端工具环境受损期间，无法通过 terminal 执行后续清理 —— 需用 execute_code / 直接 SSH 绕过
