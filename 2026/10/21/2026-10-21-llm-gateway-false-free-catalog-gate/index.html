auto 路由选中了阿拉伯语 TTS 模型：LLM 网关三层「假免费」陷阱排查实录

发表于2026-10-21|更新于2026-10-29|工程实践

一个 slice(0, 8) 让 groq 的阿拉伯语 TTS 模型成了 auto 路由主选；cost_per_1k = 0.001 常量让免费与付费在分数上平级；没有价格 = 免费 的推断让 893 条模型全部判免费（nvidia 81、electronhub 631）。我们用「签名目录 + in_catalog 硬门控」把 auto 候选从 893 清洗到 395，假阳性清零。完整复盘三层根因、修复代码、部署实测与踩坑边界。

1. 缘起 — 用户报「未知错误」，抓包发现 auto 返回了 orpheus-arabic-saudi

10 月 20 日早，用户反馈：「auto 功能有问题，应该自动筛选可用的免费模型，而不是随意找几个模型来轮换」。聊天窗口显示 common.unknownError = "未知错误"，可上游真实返回的是 403 或「requires terms acceptance」。

开启调试日志后发现：auto 真正路由的模型是 canopylabs/orpheus-arabic-saudi —— 一个阿拉伯语 TTS 模型，根本不支持聊天。它恰好排在 groq /models 列表的前 8 位，被我们的 slice(0, 8) 截取成了候选。

这是一个经典的三层假阳性组合拳：

层 症状 代码位置（修复前）
L1 选错了 auto 取上游 /models 原始顺序前 8 个，打分器只给这 8 个排序 router.ts:169 allModels.slice(0, 8)
L2 分不清 cost_per_1k = 0.001 常量，免费与付费在分数上完全平级 router.ts:310 const cost_per_1k = 0.001
L3 判全免 paid_input_per_m 全是 null →「无价格记录 = 免费」⇒ 893 条全部免费 router.ts SQL：(paid IS NOT NULL AND >0) AS paid，其余一律 free = !paid

这三层叠加，导致 auto 既选错模型（TTS）、又分不清免费付费、更满屏假阳性（nvidia 81 个免费、electronhub 631 个）。

2. 核心方法 — 破局：不再造判定算法，把目录当权威证据

2.1 修复 L1：loadRoutableModels() 替代 slice(0, 8)

上游 /models 数组顺序是任意的，打分器只能给已经选出来的候选排序，不能决定「选谁做候选」。

关键点：

  • cap 25，不是 head-of-list：LIMIT 75 取排序后的前 75，过滤后再 slice(0, 25)。NON_CHAT_MODEL_RE = /guard|moderation|embed|whisper|\/tts|audio|transcri|dall-e|image|draw|rerank|ocr|realtime|vision-|live\b|orpheus|speech|voice/i 直接把 TTS/语音/图像模型剔除。
  • free: boolean 只有「正向证据」才为 true：注释写明 True only when freeness is POSITIVELY known... Unknown pricing is deliberately NOT treated as free。

2.2 修复 L2/L3：in_catalog = 1 硬门控

移植版有三套「免费判据」互不一致：

位置 判据 问题
router.ts loadRoutableModels() paid_input_per_m > 0 记 paid，其余一律 free ← 假阳性总根源。0/893 有价格 ⇒ 全目录免费
free-detect.ts detectFreeModel() Tier1 白名单 → Tier2 零价 → Tier3 :free/-free/_free 后缀 → 否则 unknown 逻辑本身没问题，是原版精神的子集
/api/free-models 端点 又一套（遍历 detectFreeModel） 与上两者口径不同 ⇒ 页面显示 groq 0 / nvidia 81 / electronhub 631，而 router 认为三者都是「全免费」

单一事实来源：上游签名目录（https://api.freellmapi.co/v1/latest）已是权威证据——目录里全是免费模型，目录成员资格本身就是免费保证，载荷里根本没有 free 字段，因为在里面的全是免费。

硬门控 vs 软权重：原移植版用 FREE_PREFERENCE = 0.25 给免费加分（软权重），但当 nvidia 81 个假免费 都在池里时，加分毫无意义。改为 WHERE in_catalog = 1 硬门控，假阳性从源头清零。FREE_PREFERENCE 在目录干净后被删——免费优先是目录准入的自然结果，不需要打分加分。

2.3 顺带修：错误对象被吞成字符串 → “未知错误”

旧代码：executeWithFallback 链耗尽时返回 primaryResult，其中 error 是上游的裸字符串（如 {"status":403,"detail":"Authorization failed"}）。routes/chat.ts 直接 c.json({ error: res.error })，SPA 读 err.error?.message → undefined → 恒显示「未知错误」。

修复后：所有错误路径（JSON/SSE）返回标准形状 {error:{type,message}}，exhausted_chain: true + attempts: [...] 透传给前端。

3. 踩坑记录 — 反例 / 边界

3.1 三套判据并存 → 三个答案

这是最隐蔽的 bug：/api/free-models 页面显示 groq 0 / nvidia 81，而 router 认为三者全免。根因是三处各自为政：

判据源 groq nvidia electronhub
/api/free-models (detectFreeModel) 0 81 631
router SQL (!paid) 41 81 631
真实目录 (signed-catalog) ✅ 免费模型 ❌ 无免费 ❌ 无免费

教训：任何「同一语义字段」在系统里超过一套计算口径，必然产生不一致。收敛成单一函数 isKnownFree(platform, modelId, priceRecord) 供所有路径调用。

3.2 收紧判据会让候选归零 —— 迁移顺序很关键

若直接把「免费 = 有明确证据」作为硬门控，在 catalog 同步完成前，groq/zhipu 的免费候选会归零，auto 反而选不出免费模型（比现在更差）。

正确顺序：

  1. 先上 catalog-sync 同步签名目录（395 条有证据）
  2. 再把 loadRoutableModels() 改成 WHERE in_catalog = 1
  3. 目录干净后删掉 FREE_PREFERENCE

中间过渡期用「catalog 为空时才回退到运行时检测」兜底。

3.3 只认字面量 'free' —— "$10/M in" 不能 paint green

原版 priceHintOf() 三条硬规则（移植时必须保留行为）：

这是「防御性默认拒绝」的典型：unknown 一律不进 auto 候选池，显式指定模型名时仍可用。

3.4 目录 payload 里没有 free 字段 —— 不要再造判定算法

https://api.freellmapi.co/v1/latest 返回的模型列表，每条里没有 free 字段，因为「在目录里 = 免费」。我们不该在查询层再造一次「免费判定算法」，而应让目录准入成为唯一证据。

3.5 Ed25519 验签变死代码 —— 别照抄历史包袱

历史上目录有 Ed25519 签名，monthly tier 当前版本无 signature 字段。验签逻辑已成死代码，别在移植时复活它。

3.6 显式请求必须绕过门控，返回真实上游错误

in_catalog = 1 只管 auto/fusion。用户指名道姓 nvidia/01-ai/yi-large 时，仍走原逻辑，返回真实上游错误（Authorization failed），而不是被门控拦截成「模型不存在」。这保证了：

  • 实测：auto 6/6 命中 openai/gpt-oss-120b free=True
  • 实测：显式 nvidia/01-ai/yi-large → "Authorization failed"（真实上游错误）

3.7 不适用场景

场景 说明
单一上游、无免费层 没有「目录」概念，硬门控无意义
需要把「付费模型也纳入 auto」 本设计是「auto = 只用免费」；若需混合，改用软权重
目录更新频率极低 退役机制会误伤长期稳定的模型，需加保护期

4. 总结

指标 修复前 修复后 数据来源
auto 候选池 893 条 395 条 in_catalog=1 硬门控
免费模型假阳性 nvidia 81、electronhub 631、openrouter 470 清零 目录成员即免费
选中非聊天模型 ✅ orpheus-arabic-saudi ❌ NON_CHAT_MODEL_RE 剔除 正则覆盖 `tts
错误信息 「未知错误」 结构化 {type,message} + exhausted_chain 实测 chat.ts 返回
FREE_PREFERENCE 0.25（软权重） 已删（硬门控生效后多余） commit 30ec4fe router diff

核心可复用规则：

「缺失即默认为真」是通用反模式。paid_input_per_m 为 null 不等于「免费」，等于「未知」。只有正向证据（签名目录、上游字面量 'free'、双零 pricing、运营者白名单）才能把 free_status 设为 free；其余一律 unknown，不进 auto 候选池。

权威数据源出现时，删掉自研判定算法。上游签名目录已是权威免费清单，in_catalog 硬门控替代 priceHintOf、detectFreeModel、FREE_PREFERENCE 三套并存的口径，把假阳性从源头清零。

打分器只能给「已选出的候选」排序，不能决定「选谁做候选」。slice(0, N) 取上游原始顺序是典型的把「选择」让渡给上游任意排序的错误。
